# PCB Atelier

<p align="center">
  <img src="assets/branding/pcb-atelier-logo.png" alt="PCB Atelier logo" width="220">
</p>

PCB Atelier（PCB 艺术工坊）是一个面向 PCB 艺术板的创作工作台。它承接
图片处理工具与专业 EDA 之间最重复、最不顺手的一段制作工作：把创作者的视觉
素材和构图意图，转换为可预览、可检查、可制造的 PCB 生产层。

它不是完整电子 EDA，也不是完整 Photoshop。它希望把创作者目前分散在
AI、Photoshop、图片转换工具和 EDA 之间的重复工作，整理成一个可视、可复现、
可自动化的制作流程：

```text
资产 → 内容图层 → 基础图像处理 → PCB 生产层 → 2D / 3D 预览 → EDA / Gerber
```

## Motivation

PCB 艺术创作中最消耗时间的部分，往往不是某一次图片处理，而是在多个工具
之间不断重复同一组工作：

```text
调整图片
→ AI / PS / 抠图 / 黑白 / 反相
→ 导出处理稿
→ 导入 EDA
→ 指定铜、阻焊和丝印层
→ 重新调整尺寸、位置和方向
→ 查看 3D 或制造效果
→ 发现问题后返回图片工具重做
```

这种流程的问题在于，用户经常直到进入 EDA 或准备下单时，才发现沉金区域、
阻焊极性、线宽、图案尺寸或层间关系不符合预期。修改一个宽高数字，实际意味着
重新缩放、重新导入、重新对齐和重新检查。

用户真正想完成的是一块 PCB 艺术品，而不是先学会一套完整 EDA。焊盘、铺铜、
阻焊开窗、底层镜像和 Gerber 坐标是实现作品的技术手段，不应该成为普通用户
进行图片创作的主要负担。

PCB Atelier 希望把图片处理、内容层叠、生产层映射、实体预览和制造交接放在
同一个项目中。调整图片或板尺寸后，所有生产层和导出结果能够安全重算，而不是
要求用户重新完成整条导入流程。

对于普通用户，它应当是一个可以围绕最终作品完成主要操作的创作工具：简单艺术
板完成后可直接导出制造文件，或只进入 EDA 做最终确认。对于高级用户，它应当
提供类似 Sketch 的图层与对象控制，并允许精确查看、组合和导出 PCB 生产层。
复杂图片精修仍可交给 Photoshop，复杂电路仍可交给专业 EDA；后者是复杂设计和
最终复核的出口，而不应成为反复处理图片、重新定位和重新分层的主要场所。

## 产品方向

PCB Atelier 以项目为中心管理：

- 原始插画、外部处理稿、蒙版、Logo 和文字等资产；
- 可排序、分组、显隐和锁定的内容图层；
- 灰度、黑白、反相、阈值、线宽和基础蒙版等非破坏处理；
- 顶铜、顶阻焊、顶丝印及对应背面生产层；
- 板框、孔位、焊盘和焊环；
- 多生产层同时查看的精确 2D 生产预览，以及基于相同几何的 3D 材料预览；
- EasyEDA 和 Gerber 制造交接；
- 可复现、可批处理的 CLI。

未来可以增加 Agent 面板，通过稳定的 Core API 或 CLI 帮助用户修改项目、
比较参数和检查问题。Agent 只是一种操作者，不拥有独立的项目和导出逻辑。

## 技术架构

新项目直接继承 PCB_lightgraph Neo 已经稳定的跨平台技术底座：

- **Tauri 2** 提供轻量桌面外壳、文件系统集成、系统对话框、外部应用联动和
  前后端命令边界；
- **React + TypeScript** 负责界面状态、图层面板、属性检查器、主题、Canvas
  预览和用户操作；
- **Tailwind CSS v4 + shadcn/ui** 提供界面样式与基础组件；
- **独立 Rust Core** 负责项目模型、图像处理、生产层编译、制造检查与导出，
  不依赖 Tauri；
- **CLI** 与 GUI 共享 Rust Core，保证自动化、批处理和未来 Agent 调用不会产生
  另一套结果；
- **Vitest、Playwright 与 Rust 测试** 分别覆盖界面状态、桌面工作流和生产层
  契约；
- 应用图标与基础品牌资产暂时继承 PCB_lightgraph Neo，后续可以在产品方向稳定
  后独立升级。

技术架构可以继承，但旧 UI、旧工程 schema 和“一面一张图片绑定一组固定处理”
的模型不直接继承。

## 产品边界

PCB Atelier 不计划替代：

- 完整原理图、网络、封装和 PCB 布线；
- 专业绘画与复杂 PS 精修；
- 未经验证的一键老师风格复刻；
- 专业 EDA 的复杂 DRC、器件库、3D 和 PCBA 能力。

## 当前状态

项目处于产品定义和架构初始化阶段。此时优先保证：

- 不继承旧项目“一张图片绑定一组固定处理”的核心模型；
- 不以功能数量代替真实生产闭环；
- GUI、CLI 和未来 Agent 共用同一套工程与命令模型；
- 2D / 3D 预览、EDA 和 Gerber 使用同一份生产层数据；几何、尺寸、方向、极性
  和裁切必须一致，材质效果则作为可信的视觉近似。

## 与 PCB_lightgraph Neo 的关系

PCB_lightgraph Neo 是原型、算法实验场和错误案例库。

新项目可以参考其中已经验证的 Rust 算法、Gerber / EasyEDA 输出、梅琳娜工艺、
双面卡片、板框、孔位、焊环和测试资料，但不直接继承旧 UI、旧工程 schema 或
未经闭环验证的实验工作流。
