## Context

PCB Atelier 当前已经具备项目文档、正背面生产层、图片/文字对象、2D/3D 预览和
EasyEDA 交接的基础链路，但图片仍以“导入后直接放置”为主：编辑画布倾向于显示原图，
生产处理散落在预览或导出阶段，素材、处理结果和放置实例之间缺少稳定关系。其结果是：

- 编辑态与成板态存在明显认知落差，用户无法在排版时判断阈值、反相、开窗或丝印细节；
- 同一素材难以复用和替换，处理参数也难以比较、回退或跨多个放置实例共享；
- 移动对象时可能触发跨桥命令或整板重建，破坏桌面编辑器应有的连续反馈；
- 制造选项是松散的显示字段，没有成为 2D、3D、导出共同消费的版本化能力快照；
- 图层、素材、右键菜单和快捷键各自触发不同路径，容易出现行为不一致。

本变更横跨 Rust 领域模型、图片处理、工程读写、Tauri/Web 工作区契约、React/Konva
交互、3D 合成和 EasyEDA 导出。核心约束是：生产层几何为事实来源；GUI、CLI、预览和
导出必须调用同一组 Rust 领域操作；正背面继续保存物理板坐标，背面镜像仅是观看变换。

界面以大屏桌面创作为默认场景。左侧不再让“图层”和“媒体库”互相替代，而是使用可调整
高度的纵向 Dock 同时展示。窄窗口可以折叠某一区域，但不能丢失选择、展开或滚动状态。

## Goals / Non-Goals

**Goals:**

- 建立“原始素材 → 非破坏处理版本 → 放置实例 → 生产层映射”的稳定数据模型。
- 让图片在编辑画布上以可交互的生产近似轮廓显示，并与正式生产几何保持一致。
- 用一个版本化制造能力配置驱动编辑近似色、3D 材质、导出校验和工程持久化。
- 让左键编辑、右键平移、对象菜单和常用快捷键形成无冲突的指针与命令体系。
- 用整窗几何居中的三状态选择器统一左右、上下和聚焦当前面，并持久化该画板视图、主题与启动窗口方式。
- 提供默认中档的设备级滚轮缩放阻尼，以连续 delta 和指针锚定兼顾触控板与滚轮手感。
- 精简画布 HUD，只保留正/背方位与缩放百分比，把坐标、尺寸和生产层精确值交给检查器。
- 通过分级精度、对象级缓存、后台任务和 revision 校验，使拖动、选择和模式切换流畅。
- 保证 Web 测试运行时、Tauri 桌面端和 CLI 对同一工程得到可比较、可追踪的结果。

**Non-Goals:**

- 不实现完整位图编辑器、AI 抠图、复杂颜色分离、钢笔路径或电子线路布线。
- 不建设跨项目云素材库；首版素材随项目嵌入并在项目内去重。
- 不承诺屏幕颜色与实际板厂油墨批次色彩管理一致。
- 不让制造商订单页面成为运行时依赖，也不自动提交订单。
- 不改变背面对象的领域坐标或 EDA 导出方向来迎合镜像观看。
- 不兼容或迁移任何未发布的旧工程 schema；也不把设备级界面偏好写入可移植工程。

## Decisions

### 1. 四级实体分离，生产层仍是用户的编辑容器

工程模型新增或明确以下实体：

- `ProjectAsset`：不可变的原始文件字节、SHA-256、媒体类型、像素尺寸和导入信息。
- `ImageTreatment`：引用资产并保存版本化 `TreatmentRecipe`，不保存派生位图为事实数据。
- `ContentObject`：保存名称、裁切、物理尺寸、位置、旋转、锁定和分组等创作语义。
- `ProductionMapping`：把内容对象关联到正/背面的铜、阻焊开窗或丝印，并可引用处理版本、
  极性和组合方式。

左侧 UI 仍将图片、文字和图形直接展示在所属生产层下面；`ContentObject` 只是内部共享
源对象，不能恢复为用户可见的一级“内容层”。同一对象关联多个生产层时，树中可以出现
带关联标记的引用，但画布只保留一个选择框和一套物理变换。

选择此方案是因为它同时满足生产层导向的创作心智和多层共享变换。备选方案“每个生产层
复制一个对象”实现简单，但会产生可分别移动的伪副本和同步问题；“只保存最终 mask”则
无法无损调整和复用素材。

### 2. 原始资产不可变，处理配方可版本化，派生结果仅作缓存

导入时按 SHA-256 在项目内去重，原始字节嵌入工程归档。处理版本保存算法版本以及：

- alpha/白底解释；
- 灰度与明确保存的阈值；Otsu 只负责导入时或用户显式请求时重新估算该阈值；
- 反相；
- 平滑；
- 以毫米为语义的去斑、最小线宽和最小间隙处理。

流水线固定为“解码与方向归一 → 裁切/采样 → alpha 与背景解释 → 灰度/阈值 → 反相 →
平滑 → 物理尺度清理 → 二值 mask”。每次算法语义变化必须提高算法版本。缓存键至少包含
资产哈希、配方指纹、裁切、对象物理尺寸、采样间距和栅格器版本；平移与旋转只改变实例
变换，不使对象局部 mask 失效。

选择配方而非保存处理后副本，是为了支持回退、复用和跨输出一致性。备选方案“每次修改都
生成新 PNG”便于显示，却会扩大工程、隐藏算法语义，并使高分辨率导出无法可靠复算。

### 3. 单一 Rust 处理核心提供三级精度

`atelier-core` 提供无 UI 依赖的同步领域算法，调用方决定调度方式：

1. **交互代理**：限制像素边长，供导入对照和编辑画布快速反馈；
2. **成板预览**：按可见屏幕密度生成 2D/3D 纹理；
3. **正式生产**：按物理规则和导出分辨率生成确定性 mask。

三级精度允许采样密度和抗锯齿不同，但必须共享相同配方、极性、裁切和物理边界。核心返回
配方指纹、revision 和诊断信息；Tauri 使用后台线程执行，Web 测试适配器使用相同契约，
CLI 直接调用同一领域操作。

不采用浏览器 Canvas 滤镜作为主实现，因为它难以保证 CLI、3D 和导出的几何一致；浏览器
可以缩放已生成的代理，但不能独立解释处理配方。

### 4. 编辑节点显示生产近似，而不是叠加整板生产纹理

每个图片对象在 Konva 中只有一个可命中、可选择、可变换的节点。节点纹理来自对象局部
代理 mask，并按当前生产层材质近似着色；原始彩图只在媒体库缩略图和图片处理器的“原图”
一侧出现。禁止再在编辑画布上同时绘制原图节点与同一对象的整板编译纹理。

阻焊开窗、丝印和露铜的颜色来自制造配置快照。近似显示要表达轮廓、极性和材质关系，不
模拟实际油墨反射。对象拖动期间只更新客户端矩阵；手势结束后提交一个可撤销领域命令，
后台复合纹理按新 revision 更新。

备选方案“编辑态直接显示整板 ResolvedFabricationBoard”最接近最终结果，但每次变换都
需要重建整板，也会造成重复命中和重影，因此只用于预览模式和一致性检查。

### 5. 媒体库与生产层采用并行可调整 Dock

宽屏默认左侧从上到下同时显示生产层树和项目媒体库，中间有可拖动分隔条；两个区域分别
保存高度、滚动、展开和选择状态。媒体库支持文件夹、搜索、使用次数、缩略图和处理版本。

拖放采用“来源 × 落点”的显式矩阵：

- 操作系统图片 → 画板：导入/去重资产，并在落点卡面和该面当前生产层创建默认处理版本、
  实例及映射；
- 操作系统图片 → 媒体库：只导入/去重资产；
- 媒体库素材 → 画板：复用资产，在落点卡面和该面当前生产层创建新实例及映射。

画板放置先校验文件和目标层，再以单个可撤销事务提交，避免导入成功但映射失败的半完成
状态；落点转换为板上物理坐标。仅导入媒体库不创建处理映射，也不改变活动卡面。

推荐以 1440 CSS px 作为完整并行布局下限、1920 px 作为主要优化目标。空间不足时允许
把媒体库折叠为窄条或抽屉，但不以两个标签反复切换作为默认流程。分隔位置只属于本地工作
区偏好，不写入可移植工程语义。

备选方案“图层/媒体标签页”节省宽度，但频繁切换会打断用户在素材和层级之间的连续操作。

### 6. 一个三状态画板视图选择器，全局界面偏好由本地设置统一持久化

画板视图只保存一个 `canvasView` 枚举：`horizontal`、`vertical`、`focus-active`，界面
分别显示“左右”“上下”“聚焦当前面”。首次启动或本地偏好缺失时使用 `horizontal`。
`focus-active` 只隐藏非活动画板，不销毁其选择、视口或编辑状态。顶部选择器和设置页的
“默认画板视图”必须读写同一个 `UserPreferencesStore`，不得再维护独立的排列与查看模式。

三状态选择器以应用窗口边界计算几何中心，而不是在左 Dock 与右检查器之间的剩余区域内
居中；因此左右面板宽度变化不会让它视觉漂移。编辑/预览切换固定在顶部右侧并预留稳定宽度，
模式标签或内容变化不能带动控件跳动。撤销/重做从顶栏移除以降低工具栏噪声，但命令注册表、
菜单和快捷键入口不变。

设置页继续承载主题、滚轮缩放阻尼、启动窗口方式及后续设备级全局偏好。`launchWindowMode`
使用 `maximized`、`fullscreen`、`windowed` 三个稳定枚举值，默认 `maximized`；桌面端默认
逻辑尺寸为 `1440 × 900`，并以最大化普通窗口启动，既利用大屏又不默认进入系统独占全屏。
阻尼使用 `high`、`medium`、
`low` 三个稳定枚举值，默认 `medium`；高阻尼使用更小响应系数，低阻尼使用更大响应系数。
Web 测试适配器可使用浏览器本地存储，Tauri 使用应用配置存储；两者共享同一偏好 schema、
默认值、枚举校验和重置语义。偏好加载失败或字段非法时，画板视图回退到 `horizontal`、
阻尼回退到 `medium` 并允许覆盖修复，但不得影响工程加载。

画板视图、主题、启动窗口方式、缩放阻尼、Dock 尺寸和折叠状态均属于设备本地 UI 偏好，不进入 `.pcba`
归档、不触发工程脏状态，也不参与撤销/重做。选择本地全局偏好而非项目字段，是因为它们
描述用户的工作环境而非作品语义；代价是不同设备不会自动同步，这在当前无账户同步的范围
内可接受。

### 7. 指针事件由显式状态机仲裁

画布输入状态至少包括 `Idle`、`Selecting`、`MarqueeSelecting`、`Transforming`、
`PanningCandidate`、`Panning` 和 `ContextMenuOpen`：

- 左键命中对象：选择或移动对象；左键命中空白：框选；
- 右键按下：进入平移候选；移动超过设备像素阈值后平移视口；
- 右键未越过阈值且在原位置释放：对命中对象或画布打开上下文菜单；
- `contextmenu` 浏览器默认行为被统一抑制，菜单在点击外部、Esc、视口变化或命令执行后关闭；
- 滚轮/触控板缩放直接消费连续 delta，并按高/中/低阻尼映射到不同响应系数；缩放围绕指针，
  保持指针下板上物理位置不变，视口状态按正背画板分别保存。

选择状态机而非分散事件回调，是为了明确右键点击与拖动的互斥关系，也便于自动化测试。
阈值按 CSS 像素和设备输入归一，避免高 DPI 下产生误菜单。

画布 HUD 采用最小信息原则：画板边缘只保留“正面/背面”和缩放百分比。板内
`FRONT`/`BACK`、常驻手势教学、坐标读数、画板尺寸和生产层 badge 全部移除；坐标、尺寸、
生产层等精确值由右侧检查器按当前选择展示。这样减少画布遮挡和重复信息，代价是未选择对象
时不常驻显示精确数据，该取舍符合检查器作为属性事实入口的定位。

### 8. 所有入口调用统一命令注册表

命令注册表描述命令 ID、中文标题、快捷键、作用域、启用条件和领域执行函数。图层菜单、
对象右键菜单、顶部插入入口、命令面板和快捷键只负责查找并调用命令，不复制业务逻辑。

图层面板底部不常驻大号“分组/解组”按钮。多选对象存在可执行的组合命令，或当前选择包含
可解组的组合时，面板才显示紧凑上下文操作条，并仅呈现当前可用动作；没有可用动作时操作条
完全移除且不保留空白占位。操作条、对象右键菜单和快捷键调用同一命令注册表，因此启用条件、
撤销记录和错误反馈必须一致。

首版至少包括选择工具 `V`、文字 `T`、图片 `P`、Delete/Backspace 删除、复制粘贴、
创建副本、组合/解组、锁定、重命名、方向键微调、撤销/重做。输入框、文本编辑和处理参数
控件获得焦点时，单键工具与删除快捷键必须被抑制。删除关联对象时显示其多层影响，不能只
移除一个看似独立的画布副本。

撤销/重做不因移出顶栏而降级：`Cmd/Ctrl+Z`、`Cmd/Ctrl+Shift+Z` 及菜单入口继续调用相同
命令，并按历史状态正确禁用；不得为隐藏顶栏按钮而删除领域能力。

命令最终落到可撤销的 Rust 工作区操作；纯本地视口命令可留在 UI 状态中。这样 GUI、CLI
和未来自动化可以共享领域操作，而 CLI 不需要模拟键盘。

### 9. 制造能力使用版本化快照，不把网页字符串写入几何模型

工程保存 `ManufacturerProfileSnapshot`，包含制造商标识、能力版本、板材固定值、板厚、
外层铜厚、阻焊颜色、字符工艺和表面处理的稳定枚举及条件约束。首版对齐嘉立创 FR-4
艺术板常用选项，并区分：

- FR-4 基材；
- 绿、红、黄、蓝、白、哑黑、嘉立创紫等阻焊油墨；
- 标准字符与受约束的彩色丝印能力；
- 有铅喷锡、无铅喷锡、沉金、OSP 等可跨板材表达的露铜表面处理稳定枚举；
- 包括 `0.5 oz` 在内的板厚与外层铜厚稳定枚举。

稳定枚举表达“领域模型可以表示”，不等于当前制造快照允许。依据当前 JLCPCB Capabilities，
首版 JLCPCB FR-4 快照的表面处理只允许有铅 HASL、无铅 HASL 与 ENIG；OSP 仅属于铜基板
能力，必须在 FR-4 组合入口拒绝。`0.5 oz` 也不在当前 FR-4 外层铜厚能力中，必须拒绝，
不得因枚举存在而出现在可选组合或被导出声明为受支持。

线上文案和可用组合会变化，所以应用内能力表必须带版本；项目保存创建时采用的当前快照，
几何编译只消费稳定语义，供应商适配器负责把稳定枚举翻译为导出说明或下单提示。无效组合
在选择和导出前均被阻止。本变更不定义旧能力快照的读取、升级或迁移路径。

选择快照而非实时抓取订单页，是为了离线可复现和测试稳定。编辑近似调色板也来自该快照，
但会明确标注为视觉近似。

### 10. revision、防陈旧写回与性能预算是契约的一部分

工作区每个会影响派生结果的变更产生单调 revision。后台结果只有在工程 ID、对象 ID、
配方指纹和请求 revision 仍匹配时才能写入缓存或替换纹理，旧任务应尽早取消。

验收预算以发布构建、典型 2MP 素材和常规双面卡片为基准：

- 对象拖动和视口平移期间不得调用生产编译或同步 Tauri IPC，帧更新 p95 不高于 16.7 ms；
- 已缓存对象代理的选择或显隐反馈在下一帧出现；
- 参数连续输入以约 100 ms 防抖，低分辨率处理预览 p95 在 250 ms 内出现首个有效结果；
- 已有缓存时切换编辑/预览 p95 不高于 100 ms；
- 冷启动 3D 允许后台渐进生成，但 UI 必须立即响应并显示明确状态；
- 正式导出永远等待高精度结果，不能复用仅供屏幕显示的代理。

这些数字作为可测目标而非在所有硬件上的绝对保证。测试必须记录素材尺寸、构建模式和设备，
避免用开发构建偶然表现代替回归基线。

### 11. 一致性用几何黄金样例验证，不用截图相似替代

同一 fixture 在 Rust 核心、CLI、Web 适配器和 Tauri 路径中生成：

- 每个生产层的 mask 哈希或规范化轮廓；
- 物理包围盒、极性、正背方向；
- 配方与制造配置指纹；
- 3D 纹理和 EasyEDA 输出所引用的 revision。

屏幕代理可有不同分辨率，因此比较前归一到物理坐标；结构、开窗方向、镜像和尺寸必须相同。
浏览器 E2E 验证真实指针/键盘流程，Tauri 实测验证 IPC、后台任务、3D 交互和工程重开。

### 12. EasyEDA 交接使用有界误差的矢量轮廓，不把生产像素阶梯固化为图形

正式生产 mask 仍是制造事实来源，但像素格仅用于确定性采样，不应原样成为 EDA 中可见的
水平/垂直阶梯。真实 EasyEDA 工程对照表明，其原生图片同样使用线性路径，但轮廓点位于
亚像素坐标且绝大多数边不与采样轴平行。适配器因此在外轮廓与孔洞完成归属后，先执行两次
有界角点切割，把最近邻放大形成的直角节奏转换为亚像素任意方向线段，再执行确定性的闭合
Douglas-Peucker 简化；两阶段合计最大偏差限制为一个正式生产像素间距。输出继续使用
EasyEDA 稳定支持的线性复杂多边形，无需依赖其运行时图片转换 API，也不重新解释原始素材。

每个候选环必须保持绕向、非退化且无自交，否则单环回退到逐像素边界。小岛与孔洞的归属在
简化前确定，避免视觉优化改变 nonzero fill-rule 下的拓扑。这个误差预算与 25 µm 正式
采样间距相同，消除放大后的栅格阶梯，同时不声称恢复源图片中采样精度以外的细节。同一
生产层的全部外环和孔洞聚合为一个 `FILL` 图元，避免一张图片因连通岛屿被拆成数百个
EasyEDA 对象；环的绕向继续表达填充与孔洞语义。

## Risks / Trade-offs

- [物理尺度清理会让处理结果随对象尺寸变化] → 把物理尺寸纳入缓存键，尺寸调整时明确提示
  正在重算，并在历史命令中把尺寸和对应 revision 作为一个事务。
- [原始素材嵌入会增大工程文件] → SHA-256 去重、缩略图/代理不作为必存事实，并预留资源
  统计与“查找未使用素材”，但首版不自动删除仍被历史或版本引用的素材。
- [大屏 Dock 在小窗口过于拥挤] → 完整并行布局优先，窄屏仅折叠次要区域且持久化状态，不
  改变工程数据或活动生产层。
- [固定画板视图可能不适合设备尺寸变化] → 三个状态均由用户显式选择，设置页提供随时重置
  为左右；选择器按整窗居中，视图变化不修改工程。
- [右键拖动与系统上下文菜单存在平台差异] → 使用统一指针状态机、移动阈值和跨 Web/Tauri
  的真实交互测试；保留空格加左键平移作为可配置辅助但不作为默认。
- [制造商能力和选项会变化] → 版本化能力快照与适配器分离；当前未发布阶段只接受本变更
  定义的能力版本，后续发布后的升级策略另行设计。
- [代理与正式导出可能因采样差异产生细边界差异] → 共享同一配方解释器，以物理轮廓和最小
  特征诊断做跨精度测试；导出只接受正式精度结果。
- [后台任务过多造成内存与 CPU 峰值] → 按对象合并请求、取消陈旧任务、限制并发和缓存预算，
  优先处理活动卡面及可见对象。
- [快捷键与文本输入冲突] → 命令注册表集中处理作用域，E2E 覆盖输入框、重命名、文本编辑
  和模态窗口中的快捷键抑制。

## Rollout Plan

1. 在 Rust 核心定义唯一的当前 schema、能力快照、处理配方及严格反序列化与完整性校验；
   不保留旧图片、旧阈值、旧制造字段或旧能力快照的兼容分支。
2. 加入原子保存：加载或校验失败只返回带字段路径的错误，不执行自动修复、不生成迁移结果，
   也不覆盖原工程文件。
3. 加入新编译 API、缓存键和 CLI 黄金 fixture，证明当前 schema 在各运行时输出一致。
4. 接入媒体库与图片处理器，再将编辑图片节点切换为对象级生产代理。
5. 接入本地偏好存储和设置页，先验证三状态 `canvasView` 默认左右、滚轮阻尼默认中档及主题
   的跨重启恢复，再接入固定顶部控件、精简 HUD、指针状态机、命令注册表和制造配置 UI。
6. 最后让 3D 与 EasyEDA 只接受当前 revision/指纹结果，移除硬编码预览纹理和遗留旁路。

## Open Questions

- 嘉立创彩色丝印首版是只作为能力与校验提示，还是同时输出其专用生产资产格式；实现前需以
  当前官方文件要求确定。
- 处理版本的默认共享粒度是“同一资产全局复用”还是“首次放置时创建独立版本”；领域模型
  同时支持两者，UI 默认值需通过真实艺术板工作流验证。
- `P` 作为图片工具快捷键是否需要兼容中文输入法和未来钢笔工具；命令注册表允许后续改键，
  首版按当前约定实现。
- 代理缓存的工程内持久化收益是否足以抵消归档体积；首版只要求可丢弃缓存，完成性能采样后
  再决定是否随工程保存。
