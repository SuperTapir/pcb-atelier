## 为什么现在要做

PCB 艺术板创作者目前必须在图片工具与 EDA 之间来回切换：拆分图片、导入多份
素材、分配 PCB 层、反复修复尺寸与位置，直到打开 EDA 后才发现镜像、阻焊或图层
错误。旧项目 PCB_lightgraph Neo 已验证 Gerber / 嘉立创 EDA 的下游链路，但其
“一张图片 + 固定配方”的工程模型无法承载 PS / Sketch 式的自由图层编辑。

本变更建立 PCB Atelier 第一条可用的制作闭环：用户直接在正反面的真实生产层中
创作，在 2D 中检查结果，并导出到嘉立创 EDA。它是替代简单艺术板中“反复导图、
重新摆放”流程的最小垂直切片。

## 变更内容

- 新增带版本的卡片工程模型：正反面、内容图层树、物理变换、板框、基础叠层
  （基材、阻焊颜色、表面处理），以及内容到 PCB 生产层的明确映射。
- 新增类 EDA 编辑工作区：正面和背面默认作为两块独立毫米画板同时显示，用户
  点击画板决定活动卡面；生产层树、检查器、图片/文字插入、选择、拖动、缩放、旋转、
  镜像、显隐、锁定、排序、分组和撤销/重做均跟随活动卡面。
- 顶层只保留“编辑 / 预览”两个模式。编辑模式承载对象编排、生产映射、生产层显隐
  与叠层参数，用户通过左侧图层面板完成全部修改；预览模式只显示近似成板的整体
  3D 模型，支持拖拽旋转、缩放和平移查看，不承担内容或生产层编辑。
- 左侧不暴露独立“内容层”，固定显示“板体 → 正面/背面 → 铜层、阻焊开窗、丝印层”。
  图片、文字、图形和铺铜直接显示在所属生产层下；源内容对象与 `ProductionMapping`
  只作为内部真相。铜层允许基础铺铜与挖空，丝印不允许铺铜，阻焊层明确使用“添加
  开窗 / 减少开窗”语义，非法插入必须在入口处阻止。
- 同一源对象默认属于当前生产层，并可通过高级操作关联到同面的其他生产层；左侧显示
  关联关系但不得制造可独立移动的副本。
- 新增共享“板体”根节点。右侧可编辑宽高、圆角、板厚、阻焊颜色与表面处理；FR-4
  首版固定且不作为主要选项。改尺寸默认保留对象物理坐标与尺寸，不按比例缩放，并对
  超出新板框的对象给出警告。
- 每个卡面默认只允许一个基础铺铜；再次添加时选中既有铺铜，不创建重名对象。
- 新增双画板布局控制：宽屏并排、窄屏上下自适应，并允许“同时查看 / 聚焦当前面”；
  每面分别保存选择和视口，切换布局不得丢失另一面的状态。
- 将可编辑工程编译为共享生产层表示，并提供 2D 制造预览，使正反面、极性和层组合
  可被明确检查。
- 为简单双层艺术卡导出可由嘉立创 EDA 打开的工程；复用 PCB_lightgraph Neo 已验证的
  下游经验，但替换其固定配方工程模型。
- 新增非对称黄金卡片与自动化一致性检查，保证工程、预览和嘉立创 EDA 导出在尺寸、
  图层语义与正反面方向上保持一致。
- 将 Web 从硬编码 E2E 假 IPC 升级为与 Tauri 共用能力契约的真实运行面：图片插入、
  分组/解组和 3D 预览必须调用共享 Rust 应用服务；预览必须来自当前工程实际编译的
  `ResolvedFabricationBoard`，不得使用固定 `8 × 5` 纹理。

**破坏性变更**：本变更新建 PCB Atelier 工程 schema，不在运行时兼容
PCB_lightgraph Neo 工程文件。

### 明确不做的内容

- 完整栅格图像编辑器、Photoshop 替代品、自由绘画工具或自动语义拆图。
- 完整原理图、布线、器件库、电气规则或 PCBA 编辑器。
- 将用户在嘉立创 EDA 中的任意修改双向同步回 PCB Atelier。
- 摄影级 3D 材质渲染、高级制造配方、任意异形板框，以及本切片中的完整 Gerber
  制造导出。

## 能力

### 新增能力

- `card-artwork-document`：双面艺术卡、内容图层层级、物理变换和生产层映射的带版本、
  可复现工程语义。
- `card-editor-workspace`：以板体、正背面与真实生产层组织双画板，以活动生产层驱动
  图片、文字、图形、铺铜、变换与关联的类 EDA 2D 工作区。
- `production-layer-preview`：编辑模式中的共享生产层 2D 检查，以及独立预览模式中
  可旋转、缩放和平移的近似 3D 成板查看；两者都消费同一份生产几何。
- `easyeda-artwork-handoff`：从同一份已编译生产层数据导出并验证可被嘉立创 EDA 打开的
  工程。

### 修改能力

- 无。

## 影响范围

- 新增 Tauri / React 应用与独立 Rust Core，使用共享工程/命令边界，不将画布库状态
  作为工程真相。
- 第一版采用 React + Konva 作为图片、文字和交互控件的画布适配器；生产层以 Rust
  Core 编译后的少量纹理显示，并通过独立渲染接口预留未来切换 PixiJS / WebGL /
  WebGPU 的空间。Fabric.js、Filerobot Image Editor 与 SVG-Edit 仅是源码参考。
- 桌面 UI 的顶层状态改为编辑/预览；编辑模式以两个独立画板实例承载正反面的选择与
  视口，活动卡面只决定命令目标；预览模式使用独立 3D 相机状态，不改写内容或生产
  坐标。
- 提取 Tauri 与 Web 共用的 Rust `WorkspaceService` 和版本化能力契约；Web 开发/测试
  面不得再以独立 TypeScript fixture 模拟领域命令或生产结果。
- 复用 `/Users/tapir/Development/PCB_lightgraph_mac` 中导出架构、测试和 `.eprj2`
  转换的经验，但不复制其 UI 或“一张图片 + 固定配方”schema。
- 在 `reference/` 增加受版本控制的源码参考索引，第三方克隆源码不进入产品仓库历史。
