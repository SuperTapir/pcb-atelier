## MODIFIED Requirements

### Requirement: 可版本化的非破坏式图片处理配方
系统 MUST 保留原始图片，并将明确的阈值、反相、白底语义、平滑、去斑、裁切和算法版本
保存为可复现处理配方。Otsu MUST 仅在导入时或用户显式执行“重新自动估算”时计算推荐阈值，
计算结果 MUST 固化为可编辑数值，不得作为含义不明的长期模式。图片导入弹窗中的配方只有
用户确认后才可进入工程；常驻检查器中的一次连续滑块手势或一次数值编辑结束 MUST 作为一个
最终配方命令进入撤销/重做历史。手势或输入尚未结束的临时 draft MUST 保持在工程 document
之外，不得覆盖原始资产字节或为每个中间值创建历史命令。

#### Scenario: 调整阈值后撤销
- **WHEN** 用户连续拖动由 Otsu 初始化的丝印图片阈值并结束本次调整
- **THEN** 系统必须只提交最终配方作为一个可撤销命令，撤销后恢复旧配方和对应生产轮廓，原始图片和放置变换保持不变

#### Scenario: 取消尚未确认的图片导入
- **WHEN** 用户在图片导入弹窗调整多个参数后选择取消
- **THEN** 工程 document、revision、撤销历史、原始资产引用和正式生产输出必须保持打开弹窗前状态

#### Scenario: 结束常驻检查器的一次滑块手势
- **WHEN** 用户在已存在图片的检查器中按下并拖动滑块后释放指针
- **THEN** 从按下到释放期间的中间 draft 不得写入历史，释放时的最终配方必须作为一个命令提交，之后关闭检查器不得回滚已完成手势

#### Scenario: 重新自动估算阈值
- **WHEN** 用户对当前图片显式执行“重新自动估算”
- **THEN** 系统必须使用 Otsu 计算新建议值、将该值显示并保存为普通可编辑阈值，且不得保留“自动模式”状态

### Requirement: 导入与检查器实时对照
系统 MUST 在图片导入和后续编辑中同时提供完整原图与当前生产层结果，并在参数变化时以
latest-only 方式更新处理轮廓。源图片在一次活跃交互会话中 MUST 只注册和解码一次；注册完成后的
预览请求 MUST 只携带稳定源句柄、配方、物理尺寸、代理精度和 generation，不得重复发送完整
源图片字节。活跃会话 MUST 固定其 prepared source；内存预算只可回收未被会话引用的数据或
可重建的缩放层/代理，不得静默逐出 prepared source 后在同一会话重复解码。确认插入后，编辑
画布默认 MUST 显示处理后轮廓；原图只能作为显式临时对照。

#### Scenario: 导入彩色人物图到丝印层
- **WHEN** 用户连续调整阈值、反相和平滑参数
- **THEN** 右侧结果必须持续显示最新已完成的黑白轮廓，处理中保留上一帧且不得空白闪烁，并标出因最小特征规则被删除或修复的区域

#### Scenario: 注册后的连续预览
- **WHEN** 已注册的 PNG 或 JPEG 在同一处理会话中产生多个参数预览请求
- **THEN** 每个请求不得再包含源图片字节，后端必须复用已完成方向归一和解码的源数据

#### Scenario: 较慢结果晚于新参数返回
- **WHEN** generation 较旧的形态学处理在较新的阈值预览之后才完成
- **THEN** 系统必须丢弃旧结果，画面、诊断和当前配方指示不得回退

#### Scenario: 临时查看原图
- **WHEN** 用户在画布中选择已处理图片并启用“查看原图”
- **THEN** 系统可以临时覆盖显示完整原图，但选择框、物理变换、生产配方和导出结果不得改变

### Requirement: 同一 Rust 流水线生成所有生产结果
交互代理、3D 预览、CLI、EasyEDA 和未来 Gerber 输出 MUST 使用同一版本化 Rust 图片处理
语义。交互代理 MAY 使用预解码源数据、缩放金字塔和较粗栅格以降低延迟，正式输出 MUST 使用
正式采样精度；两者的阈值、极性、裁切、物理清理和方向语义 MUST 相同，并携带相同处理配方
指纹。在代理像素间距可表达的特征范围内，交互与正式结果 MUST 保持拓扑一致；宽度、直径或
间隙小于两个代理像素的特征 MAY 在粗代理中暂不可见，但不得改变正式输出，界面 MUST 将其
视为需要更高精度确认的细节。交互缓存和 draft MUST 为可丢弃派生数据，不得成为 `.pcba`
工程真相。

#### Scenario: 比较交互代理与正式导出
- **WHEN** 同一图片配方分别以交互和正式导出精度生成 mask
- **THEN** 对宽度、直径和间隙均不小于两个交互代理像素的结构，降采样后的正式 mask 与交互代理必须在约定容差内边界和拓扑一致，且极性、裁切和正背方向完全一致

#### Scenario: 清空所有交互缓存
- **WHEN** 用户保存工程、关闭应用并清空已解码源图、缩放金字塔和代理纹理缓存
- **THEN** 系统必须仅凭 `.pcba` 中的原始资产和最终配方重建相同指纹的正式生产结果

## ADDED Requirements

### Requirement: 图片交互会话具有受控资源生命周期
系统 MUST 为尚未确认的导入和已存在图片的临时配方编辑建立显式交互会话。会话 MUST 引用
原始资产或临时源句柄，缓存方向归一后的像素、灰度数据和按需缩放代理，并在确认、取消、
工程关闭或会话超时后释放不再被引用的资源。缓存 MUST 受字节预算约束，不得只按对象数量
保留可能无限增大的纹理。活跃会话引用的 prepared source MUST 固定并计入预算；若新会话无法
在预算内建立，系统 MUST 返回可操作的资源错误，不得通过同一会话反复解码规避预算。

#### Scenario: 取消大型图片导入
- **WHEN** 用户导入大型图片、生成多个代理后取消对话框
- **THEN** 临时源句柄和无其他消费者的解码/代理缓存必须可被释放，且工程中不得残留资产、处理或实例

#### Scenario: 会话超时释放资源
- **WHEN** 交互会话超过规定空闲时间且没有检查器、画布或导入弹窗消费者
- **THEN** 运行时必须释放句柄引用并让 prepared source 和代理进入可回收状态，后续请求必须显式建立新会话

#### Scenario: 检查器和画布需要同一代理
- **WHEN** 检查器与画布同时请求相同资产、配方指纹、物理尺寸和精度档位
- **THEN** 系统必须合并请求并复用同一编码结果与客户端纹理，不得分别执行图片处理
