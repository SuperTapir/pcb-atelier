## Why

当前图片导入和参数调整把每一次短暂滑块位置都当成接近正式编译的请求：前端重复传输完整图片、
写入工程历史，后端重复解码并生成 PNG 代理，检查器和画布还可能并行请求不同精度。真实图片下
单次预览已达到数百毫秒，旧任务继续占用 CPU 和纹理资源，导致滑块反馈、图片拖动和整体画布操作
明显卡顿。

本变更要把“持续交互中的快速近似反馈”与“确认后可复现的正式生产结果”拆成两条有明确一致性
边界的流水线，使图片参数可以像成熟 EDA 一样持续实时预览，同时保留 PCB Atelier 对物理尺寸、
拓扑、生产层极性和正式导出的严格保证。

## What Changes

- 图片导入先注册一次源资产或临时 draft，后续预览请求只发送稳定句柄、配方和物理尺寸，不再
  重复以 JSON 数组传输完整图片字节。
- 参数拖动期间只修改本地 draft，不写工程 document、不创建 undo step；在确认或明确提交时
  才将最终配方作为一个可撤销领域命令保存。
- 建立 latest-only 交互调度：每个图片对象至多保留一个有效预览任务，旧任务可在阶段边界取消，
  陈旧结果不得覆盖较新预览。
- 源图只解码和方向归一一次，并缓存灰度/缩放金字塔；交互预览使用受观察窗约束的代理分辨率，
  检查器与画布复用同一代理结果和纹理。
- 拖动、缩放和旋转期间只变换现有客户端纹理，不触发图片解码、处理编译、同步 IPC 或正式
  document 更新；手势结束后仍只提交几何命令。
- 确认处理、2D/3D 正式预览、CLI 和 EDA/Gerber 导出继续使用版本化 Rust 正式流水线；交互代理
  必须保持方向、极性、裁切和拓扑语义一致，并通过黄金样例与正式输出比较。
- 增加真实图片负载下的交互性能契约、浏览器/Tauri 回归和可观测计数，防止重复字节传输、
  重复编译或拖动期间编译再次出现。
- 非目标：本变更不新增焊盘、钻孔、局部铺铜等内容类型，不把 PCB Atelier 扩展为完整图像编辑器，
  也不以只保存矢量轮廓取代“原始资产 + 非破坏配方”的工程真相。

## Capabilities

### New Capabilities

无。该变更收紧现有图片处理和生产预览能力的交互性能与一致性契约。

### Modified Capabilities

- `non-destructive-image-treatment`: 将实时对照改为一次注册源图、draft 编辑、latest-only
  代理预览和确认时单次提交，并规定交互代理与正式处理的职责边界。
- `production-layer-preview`: 要求检查器与画布共享对象代理，图片手势期间零处理编译，并为真实
  图片负载定义响应时间、并发和预览到正式输出的一致性验收。

## Impact

- 前端：`ImageImportDialog`、`ImageTreatmentEditor`、预览协调器、画布代理缓存与图片纹理生命周期。
- Tauri/Web bridge：新增图片 draft 注册、按句柄预览、释放 draft 和紧凑 PNG 代理返回契约。
- Rust：解码与灰度金字塔缓存、可协作取消的阶段化调度、共享代理缓存和正式编译边界。
- 工程与历史：schema 无需兼容已发布版本；源资产和最终配方仍是领域真相，交互 draft 与派生缓存
  不进入 `.pcba`。
- 验证：使用真实 PNG/JPEG 记录传输字节、编译次数、主线程帧时间和预览延迟，并用同一配方的
  交互代理、正式 mask、3D 与 EasyEDA 黄金输出比较方向、极性、裁切、拓扑和物理边界。
