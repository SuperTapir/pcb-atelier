## ADDED Requirements

### Requirement: 带版本的双面卡片工程
系统 MUST 将艺术卡保存为带 schema 版本的工程，并且必须包含物理板框、基础叠层、正面
与背面内容，以及可复现生产层编译所需的资产引用和参数。

#### Scenario: 创建基础卡片工程
- **WHEN** 用户创建一个标准卡片工程
- **THEN** 系统创建带正面、背面、毫米尺寸板框和默认基材/阻焊/表面处理的带版本工程

### Requirement: 内容图层树
系统 MUST 支持图片层、文字层和组；每个内容层必须具有稳定 ID、名称、显隐、锁定、
是否参与生产导出、排序、父组关系和以物理单位表示的变换。显隐与是否参与生产导出
必须是独立状态。

#### Scenario: 保存分组后的内容
- **WHEN** 用户将图片层和文字层放入一个组并保存工程
- **THEN** 重新打开后层级、顺序、可见性、锁定状态、导出参与状态和物理变换必须保持不变

#### Scenario: 隐藏内容但保留生产输出
- **WHEN** 用户隐藏一个仍启用生产导出的内容层
- **THEN** 内容画布不得显示该层，但生产编译仍必须包含其已启用映射

### Requirement: 内容层与生产层分离
系统 MUST 将内容层与 PCB 生产层分开保存。生产映射必须明确目标面、目标层和组合语义，
且不得把画布库对象 JSON 作为生产层的真相来源。

#### Scenario: 一个内容映射到多个生产层
- **WHEN** 用户将一个图片层映射到顶铜和顶阻焊开窗
- **THEN** 工程必须保存两项明确映射，并能在后续编译中独立生成这两个生产层

### Requirement: 板体参数可编辑且不缩放内容
系统 MUST 将宽度、高度、圆角半径、板厚、阻焊颜色和表面处理保存为共享板体参数。
首版基材 MUST 固定为 FR-4。修改板框 MUST 默认保留既有对象的物理坐标和实际尺寸，
不得自动按比例缩放内容。

#### Scenario: 缩小板体后对象越界
- **WHEN** 用户缩小板体导致既有对象部分或全部位于新板框外
- **THEN** 系统必须保留该对象的坐标与尺寸、给出明确越界警告，并让生产裁切、双画板、3D 预览和导出使用新板框

### Requirement: 每面唯一基础铺铜
系统 MUST 默认限制每个卡面最多一个基础铺铜源对象。该约束 MUST 在领域命令中执行，
不能只依赖 UI 隐藏按钮。

#### Scenario: 重复创建基础铺铜
- **WHEN** 当前卡面已经存在基础铺铜且再次请求创建
- **THEN** 系统必须返回既有铺铜的稳定 ID，不得创建第二个同名或重叠铺铜

### Requirement: 统一物理坐标与背面语义
系统 MUST 以整数微米保存生产语义坐标；正面和背面都必须保存为板自身坐标，背面镜像
不得写入持久内容变换。

#### Scenario: 切换背面观看方向
- **WHEN** 用户切换到背面查看
- **THEN** 系统仅在视图中应用背面观看变换，工程中保存的背面对象坐标不得改变
