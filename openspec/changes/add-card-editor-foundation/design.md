## 背景

PCB Atelier 当前只有产品定义，尚未建立可编辑工程或桌面画布。相邻的
PCB_lightgraph Neo 已证明“工程状态 → Rust Core → 生产板 → Gerber / 嘉立创 EDA”
的单向下游链路可行，也留下了方向、极性和旧 `LayerSet` 丢失背面层语义等问题。

本轮必须先建立新的上游模型：创作者在卡片正反面的真实生产层中直接组织图片、文字、
图形和铺铜；内部仍由源内容对象、显式生产映射和统一编译保证编辑能力与制造语义。
目标是实现一条可操作、可导出、可验证的简单艺术卡闭环，而不是在旧工程模型上继续
堆配方。

## 目标与非目标

**目标：**

- 提供熟悉、顺畅的 2D 画布操作：插入图片/文字，选择、拖动、摆放、缩放、旋转、
  镜像、锁定、分组、排序及撤销/重做。
- 默认同时显示正面与背面两块独立画板，并保留各自的选择和视口状态。
- 左侧只暴露板体、正反面及其真实生产层；源内容与生产映射只作为内部模型存在。
- 把同一份编译后的生产数据用于 2D 预览和嘉立创 EDA 导出。
- 提供只读、可旋转缩放和平移的整体 3D 成板预览。
- 首个垂直切片可导出一个可打开的 `.eprj2` 简单双层艺术卡，并验证非对称样本的方向。

**非目标：**

- 用画布库的对象 JSON 取代领域工程文件，或从前端直接拼装 EDA 文件。
- 完整 PS、矢量路径、原理图/布线、Gerber 直出、照片级 3D 渲染或 EDA 双向同步。
- 支持任意异形板框、复杂孔槽、动态覆铜或不经验证的工艺组合。

## 决策

### 1. 领域工程、画布适配器和生产板分为三层

```text
AtelierDocument（可保存的领域工程，毫米单位）
  ├── CardFace(front / back)
  │     └── SourceObject tree（内部 image / text / group / mask，变换与锁定）
  └── ProductionMapping（内部源对象 → 六个生产层）
             ↓ 解析资产、文字与映射
FabricationPlan（带来源追溯的待栅格化操作）
             ↓ 固定 25 µm 生产网格统一编译
ResolvedFabricationBoard（六张 bit mask、板框/孔与编译清单；导出的唯一输入）
             ├── 2D production preview
             └── JLCEDA adapter → .epro2 → .eprj2
```

`AtelierDocument` 是 Rust Core 所有权模型，序列化为版本化项目包。编辑工作区同时
按生产层投影正面与背面中可编辑的源对象，并把用户手势转换成同一套领域命令；画布内部
对象状态不得被保存为工程真相。这样 GUI、CLI 和未来 Agent 可以调用相同 `InsertLayer`、
`TransformLayer`、`SetLayerLock`、`MapLayer` 等操作。

选择这一结构而不是直接扩展 Neo 的 `ProjectDocument`，因为后者是“源图 + recipe +
mask”的生成式模型，无法表达可选中、排序和独立变换的对象树。它也避免让导出器
重新解释画布坐标、底面镜像或阻焊极性。

`FabricationPlan` 不能被预览或导出器当作最终生产数据，因为其中仍可能包含资产引用、
文字和变换。Core 必须在一次确定性编译中把图片与文字解析到固定的 25 µm 生产网格，
并按映射顺序完成 Add/Subtract 组合。`ResolvedFabricationBoard` 的每个生产层保存
最终 bit mask，同时保留逐操作 mask 与来源 ID 供 UI 追溯。生产预览只采样最终 mask；
嘉立创适配器只把同一 mask 多边形化，二者不得再次读取素材、文字或画布节点。

生产网格的原点、物理尺寸、像素间距、栅格器版本、字体/阈值版本和输入哈希写入编译
清单。网格不能随视口缩放改变。首版默认 25 µm/px，使 100 µm 特征至少有 4 个像素；
若资源限制要求调整，必须作为显式、可追踪的编译参数并重新通过黄金样本，而不是由
各导出器自行降采样。文字必须使用可识别版本的固定或工程内嵌字体完成栅格化，不能
依赖不同机器上的同名字体默默替换。图片的生产覆盖率固定为
`alpha × (1 - luminance)` 并以版本化阈值二值化：透明区域和白色背景不产生材料，
深色图形产生材料；裁切矩形必须位于归一化素材边界内。点文字保留显式换行，定宽
文字按字符推进换行并裁切到内容框。以上规则均属于栅格器版本的一部分。

### 2. 2D 编辑采用 React + Konva，3D 预览采用独立渲染器

React + Konva 负责图片、文字、选择框、控制点和吸附线。它与 React 数据流匹配，
并允许将静态背景、内容对象和拖动对象放入少量独立 Canvas Layer，只刷新发生变化的
部分。适配器只负责把领域 `ContentLayer` 投影为 Konva 节点，并在交互完成时提交
领域命令；拖动过程可以本地预览，但不得绕过命令历史。文字输入使用定位在画布上的
原生 DOM `textarea`，提交后再更新领域文字层。

首版固定使用四类渲染层，而不是为每个 PCB 业务层创建一个 Konva Layer：

1. 不参与命中检测的基材、板框和网格；
2. Rust Core 编译出的生产层预览纹理；
3. 可交互的图片、文字和组；
4. 选择框、控制点、吸附线及拖动中的临时对象。

铜、阻焊和丝印不得展开为大量 Konva 图元。Rust Core 将
`ResolvedFabricationBoard` 的六张 bit mask 转换为少量预览纹理，原始高分辨率图片
在画布中使用按视口分辨率生成的代理图，完整原图只用于统一编译。生产预览通过
`ProductionRenderer` 接口接入；第一版可由 Konva 显示纹理，
后续可在不修改领域工程和编辑命令的前提下替换为 PixiJS / WebGL / WebGPU。

预览模式通过独立的 `BoardPreviewRenderer` 消费同一份
`ResolvedFabricationBoard`。第一版采用 Three.js（React Three Fiber 与轨道相机控制）
构建具有真实板宽高比例、圆角板框、孔和厚度的整体板体，并将六张最终生产 mask 与
`StackupPreset` 合成为正反面材质。用户可以拖动旋转、滚轮缩放和平移相机，但不能在
预览中修改内容或生产映射。3D 材质只承诺接近实际成板的颜色和层叠关系；生产几何、
方向和开窗必须来自最终 mask，不能另做一套近似栅格化。

Fabric.js 的对象编辑能力更开箱即用，但单画布重绘和对象缓存更容易在大图、复杂分组
及频繁 viewport zoom 时产生内存、缓存重建和画质取舍，因此不作为默认实现。PixiJS
拥有更高的 GPU 渲染上限，但缺少文字输入、Transformer、对齐、图层编辑和撤销等
编辑器语义，本轮只保留为生产预览升级方向。

实现前仍需用可执行基准验证 React + Konva，而不是凭库的宣传判断。基准至少覆盖
正背两块画板合计 200 个可编辑对象、多张代理图片、六张生产层纹理、连续缩放和拖动；
非活动画板应避免无意义的高频重绘。目标机器上拖动
与缩放不得持续低于 45 FPS，典型交互目标为 60 FPS，重复切面和显隐不得导致内存
持续增长。未达到门槛时先检查代理图、命中检测、分层和缓存策略；仍未达到才更换
渲染适配器，不改变领域模型。

### 3. 坐标、正反面与工艺层具有不可变的明确语义

- 内部物理单位使用整数微米；前端显示与编辑使用毫米。
- `front` 与 `back` 都保存为板自身坐标，不在数据层预先镜像。
- 生产层固定为 `topCopper`、`topSolderMaskOpen`、`topSilkscreen`、
  `bottomCopper`、`bottomSolderMaskOpen`、`bottomSilkscreen`，外加板框和钻孔。
- 阻焊层保存“开窗”语义；编译或导出时不得以“覆盖油墨”再次反相。
- 正面查看直接显示板坐标；背面查看只在视图变换中镜像。导出适配器按嘉立创 EDA
  的格式契约转换，不能依赖屏幕坐标。

源对象可映射到一个或多个生产层，并可指定“添加”或“挖空”组合。UI 不暴露独立的
“内容层”：左侧生产层既是工作上下文，也是源对象的唯一可见归属入口。在生产层下
插入时，系统自动创建内部源对象并建立合法映射；“关联到其他生产层”只增加映射，
不复制源对象。多个生产层下出现的关联项必须共享同一源 ID，并明确显示关联标记，
任何一处移动都修改同一个物理对象。

生产层是带规则的编辑容器，插入入口与领域命令都执行相同校验：

| 生产层 | 合法内容与操作 |
| --- | --- |
| 铜层 | 图片、文字、图形、基础铺铜、挖空 |
| 丝印层 | 图片、文字、普通图形；禁止铺铜 |
| 阻焊开窗 | 图片、文字轮廓、图形；操作命名为“添加开窗/减少开窗” |

非法操作必须在入口处禁用或给出原因，不能延迟到导出阶段才报错。

基础铺铜使用可撤销的领域源对象表达，而不是直接修改编译结果。每个卡面首版最多一个
基础铺铜；再次执行“添加基础铺铜”返回并选中已有对象，不创建同名副本。铺铜带明确
板边间距且只允许映射到当前面的铜层；挖空仍由显式 `Subtract` 映射表达。

`板体` 是正反面共享的根节点。其检查器编辑宽度、高度、圆角半径、板厚、阻焊颜色和
表面处理。首版基材固定为 FR-4，不在主要界面提供材料选择。修改板体尺寸只更新板框，
保持所有对象的物理坐标和实际尺寸，不自动缩放；越界对象产生明确诊断。正背画板、
生产裁切、3D 预览和 EDA 导出均消费同一板体参数。

### 4. 编辑与预览是唯一顶层模式

对 Sketch、Figma、Photoshop 与嘉立创 EDA 的交互调研表明，稳定且易迁移的结构是：
左侧层级、中间画布、右侧上下文检查器和克制的顶部工具栏。PCB Atelier 将生产层设计
成带合法性规则的编辑容器，同时用内部源对象保留专业图像编辑器所需的变换、分组、
锁定与多层关联能力。

顶层只保留两个模式：

- **编辑**：完成图片、文字、图层、位置变换、生产层映射、阻焊开窗、丝印、铜层与
  基础铺铜等全部创作工作；
- **预览**：像嘉立创 EDA 的 3D 预览一样展示整体成板，允许旋转、缩放和平移，但只读。

编辑模式默认同时显示正面与背面两块独立画板。宽空间并排显示，空间不足时上下排列；
点击任一画板后将其设为活动卡面。左侧树、右侧检查器、插入图片/文字及生产层操作都
跟随活动卡面。布局控制提供“同时查看/聚焦当前面”；聚焦仅改变布局，不销毁另一面的
选择或视口。两面分别保存选择路径和 `viewport`，活动卡面与工具也互相独立。背面
观看镜像只能存在于对应画板的视图变换中。

左侧固定为以下统一树，不再存在“内容”卡片或一级入口：

```text
板体
正面
├── 铜层
├── 阻焊开窗
└── 丝印层
背面
├── 铜层
├── 阻焊开窗
└── 丝印层
```

图片、文字、图形和铺铜直接显示在所属生产层下。选择生产层后，插入工具立即按该层规则
变化，并自动建立合法映射。关联到多个生产层的条目是同一源对象的引用，带清晰关联标记，
不能被当成可独立漂移的副本。临时显隐/隔离只控制检查，`exportEnabled` 才决定源对象
是否参与编译和导出，二者不得复用同一开关。

右侧检查器随选择变化：选择对象时编辑变换、铺铜参数与生产层关联；选择 `板体` 时编辑
宽高、圆角、板厚、阻焊颜色和表面处理。板体缩小时立即标记越界对象但不移动或缩放它们。
2D 生产层检查属于编辑模式内部的高级能力，不再占用顶层导航。

图片可通过文件选择、拖放或粘贴插入，默认等比适配卡片并居中，插入后立即选中；
替换图片资产保留变换、层级与生产映射。文字支持点击建立点文字、拖动建立定宽文字，
双击或 Enter 进入编辑，Escape 退出。画布首先选择组或父对象，双击或 Enter 下钻，
修饰键可深选，重叠对象可从指针下候选列表选择。

锁定对象不响应画布命中，让用户可以选到其下方对象，但它仍可在生产层树中被选中、
解锁和查看。锁定同时阻止画布与检查器变换。精确检查器统一使用毫米；方向键进行
小步微调、Shift 加速。首版吸附网格、板边、对象边与中心，显示对齐参考线，并允许
临时绕过吸附。上述规则减少创作过程中的模式错误，同时保留生产结果的可解释性。

### 5. Web 与 Tauri 共用真实工作区能力契约

Web 版不能再以 TypeScript E2E 假 IPC 充当产品后端。工作区状态、图片插入、分组、
解组、生产编译和预览读取被收敛到 Rust `WorkspaceService`；Tauri command 只是薄适配层。
由于当前 Core 仍依赖原生归档与 SQLite，首版 Web 开发与测试通过本地 Rust bridge 调用
同一服务，并使用版本化 JSON/二进制能力契约，而不是为了赶进度复制一份浏览器状态机。

Web bridge 至少支持当前 revision、`insert_image_asset`、`group_layers`、
`ungroup_layer` 和 `get_board_preview`。3D 预览必须消费当前工程编译得到的
`ResolvedFabricationBoard`；硬编码 `8 × 5` 纹理只能存在于孤立组件单元测试，不能进入
Web 产品或 E2E 运行路径。契约测试对同一命令序列比较 Web bridge 与 Tauri adapter 的
文档 revision、源对象/映射结果和生产板哈希，避免两端能力继续漂移。

### 6. 嘉立创 EDA 是单向、可验证的下游出口

Rust Core 从 `ResolvedFabricationBoard` 生成公开 EDA 归档，再复用并隔离 Neo 已验证的
`.epro2 → .eprj2` 转换及结构校验。艺术图形导出为静态生产图元，避免使用会因网络、
避让或孤岛规则重建的动态铺铜。

导出仅承诺 PCB Atelier → 嘉立创 EDA。用户在 EDA 中增加的电路或手工图元不回写；
再次导出创建一个新的下游版本。首版限制为矩形/固定圆角矩形双层卡片、无原理图与
网络、基础圆孔/无孔，以及六个生产层中的已支持图层；不支持的映射必须在导出前失败
并说明原因，不能静默丢弃。

### 7. 一致性以生产几何测试，而不是肉眼渲染测试保证

建立包含 `F` / `B` 标记、偏心孔、非对称图片和文字的黄金卡片。测试必须断言：

1. 相同领域命令经 GUI 与 CLI 产生等价的 `AtelierDocument`；
2. 2D 生产预览与 `ResolvedFabricationBoard` 的层、尺寸、原点和极性一致；
3. `.eprj2` 结构可验证，重开/解析后保留预期层、尺寸和非对称方向；
4. 快速连续变换不会由旧 revision 覆盖较新的预览或导出结果。

Neo 的 revision 队列、临时文件后校验再原子替换、导出 preflight 等机制可以复用为
实现经验，但需要在新 Core 的类型上重新实现。

## 风险与取舍

- [Konva 仍是 Canvas2D，未来无法承载十万级独立生产图元] → 生产层只以编译纹理
  显示；保持 `ProductionRenderer` 可替换，达到真实瓶颈后迁移至 PixiJS/WebGL/WebGPU。
- [高分辨率图片导致缩放卡顿或内存激增] → 画布使用分辨率代理图和按需缓存，原图仅
  由 Core 在编译/导出时读取；用可重复性能场景验证而非主观体验。
- [双画板同时显示导致重复渲染和状态串扰] → 两面使用独立选择/视口状态，非活动面
  节流重绘，并用活动卡面和插入目标的交互测试约束。
- [3D 预览被误认为照片级打样结果] → UI 明示“效果预览”，几何只消费最终生产 mask，
  对材质近似与实际工艺差异给出说明。
- [同一源对象关联多个生产层后看起来像多个独立副本] → 关联项共享源 ID、显示关联标记，
  任何编辑都路由到同一对象；最终编译纹理保持只读。
- [Web 与 Tauri 各自实现状态机导致功能与预览漂移] → 两端只适配同一
  `WorkspaceService`，以契约测试比较 revision、映射结果和生产板哈希。
- [画布像素坐标与生产毫米坐标漂移] → 所有持久变换以微米保存；适配器只做双向换算，
  并用非对称黄金样本测试。
- [底面镜像或阻焊极性在导出时出错] → 只在命名的 view/export transform 中转换；
  禁止导出器读取屏幕状态；对每层断言方向和极性。
- [旧 EasyEDA 转换器隐藏旧 LayerSet 限制] → 在新 `ResolvedFabricationBoard` 六层接口外构建
  适配器，先为不支持的层明确报错，不做静默降级。
- [范围膨胀为完整 PS/EDA] → 以本提案的卡片、图片/文字、基础层映射与单向交接为
  每个任务的验收边界。
