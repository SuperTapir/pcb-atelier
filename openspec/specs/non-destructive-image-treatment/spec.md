# non-destructive-image-treatment Specification

## Purpose
定义从原始图片到可复现生产结果的非破坏处理、制造约束与跨运行时一致性，确保原始资产、
可编辑配方、交互代理和正式生产输出彼此可追溯，并在不同精度和运行入口保持相同物理语义。

## Requirements
### Requirement: 可版本化的非破坏式图片处理配方
系统 MUST 保留原始图片，并将明确的阈值、反相、白底语义、平滑、去斑、裁切和算法版本
保存为可复现处理配方。Otsu MUST 仅在导入时或用户显式执行“重新自动估算”时计算推荐阈值，
计算结果 MUST 固化为可编辑数值，不得作为含义不明的长期模式。修改配方 MUST 进入撤销/
重做历史，不得覆盖原始资产字节。

#### Scenario: 调整阈值后撤销
- **WHEN** 用户修改由 Otsu 初始化的丝印图片阈值后执行撤销
- **THEN** 系统必须恢复旧配方和对应生产轮廓，原始图片和放置变换保持不变

#### Scenario: 重新自动估算阈值
- **WHEN** 用户对当前图片显式执行“重新自动估算”
- **THEN** 系统必须使用 Otsu 计算新建议值、将该值显示并保存为普通可编辑阈值，且不得保留“自动模式”状态

### Requirement: 导入与检查器实时对照
系统 MUST 在图片导入和后续编辑中同时提供原图与当前生产层结果，并在参数变化时更新
处理后轮廓。确认插入后，编辑画布默认 MUST 显示处理后轮廓；原图只能作为显式临时对照。

#### Scenario: 导入彩色人物图到丝印层
- **WHEN** 用户调整阈值、反相和平滑参数
- **THEN** 右侧结果必须即时显示将进入丝印层的黑白轮廓，并标出因最小特征规则被删除或修复的区域

#### Scenario: 临时查看原图
- **WHEN** 用户在画布中选择已处理图片并启用“查看原图”
- **THEN** 系统可以临时覆盖显示原图，但选择框、物理变换、生产配方和导出结果不得改变

### Requirement: 物理尺度的可制造性处理
去斑、最小区域、最小线宽和最小间距 MUST 使用毫米或平方毫米表达，并基于实例的最终物理
尺寸计算，不得把含义不明的像素滑块作为生产约束。系统 MUST 区分建议修复、实际修复和
无法可靠制造的警告。

#### Scenario: 删除过小孤岛
- **WHEN** 当前配方要求删除小于 `0.15 mm²` 的孤立区域
- **THEN** 无论原图像素尺寸或交互代理分辨率如何，正式生产 mask 都必须按同一物理面积规则删除孤岛

#### Scenario: 细节低于制造能力
- **WHEN** 处理结果包含低于当前制造配置最小线宽的眼睫或文字笔画
- **THEN** 系统必须高亮风险并允许用户选择保留、加粗或删除，不得静默声称结果可制造

### Requirement: 一个实例允许分层处理但只有一套变换
同一图片实例 MAY 为铜、阻焊开窗和丝印关联不同处理版本，但实例 MUST 只有一个源资产、
裁切和物理变换。编辑画布和命中测试不得为不同处理版本创建可独立移动的副本。

#### Scenario: Logo 同时用于铜和阻焊开窗
- **WHEN** 用户为同一 Logo 的铜映射选择原始阈值，为阻焊开窗映射选择膨胀后的轮廓
- **THEN** 两层必须生成不同合法 mask，但拖动任一生产层入口只更新同一个 Logo 实例的物理坐标

### Requirement: 同一 Rust 流水线生成所有生产结果
交互代理、3D 预览、CLI、EasyEDA 和未来 Gerber 输出 MUST 调用同一版本化 Rust 图片
处理流水线。不同用途 MAY 使用不同栅格间距，但阈值、极性、裁切、物理清理和方向语义
MUST 相同，并携带处理配方指纹。

#### Scenario: 比较交互代理与正式导出
- **WHEN** 同一图片配方分别以交互和正式导出精度生成 mask
- **THEN** 降采样后的正式 mask 与交互代理必须在约定容差内边界一致，且连通关系、极性和正背方向完全一致

### Requirement: 图片实例显式声明生产模式
每个 `ImageTreatment` MUST 保存必填且版本化的 `productionMode`。当前 schema 仅允许
`monochromeMask` 与 `colorOriginal`；新建处理默认 MUST 为 `monochromeMask`。
`colorOriginal` MUST 保留原始资产字节、裁切和唯一物理变换，不得把单色处理 mask
冒充彩色生产资料。

#### Scenario: 未发布 schema 缺少生产模式
- **WHEN** 系统读取缺少 `productionMode` 的当前 schema 工程
- **THEN** 系统必须拒绝该工程并指出 schema 不完整，不得静默迁移或猜测生产模式

#### Scenario: 创建普通图片处理
- **WHEN** 用户未显式选择彩色原图生产模式就创建图片处理
- **THEN** 系统必须保存 `productionMode = monochromeMask`，并继续由版本化 Rust 配方生成生产 mask

### Requirement: 彩色原图模式受素材、生产层和制造能力约束
`colorOriginal` MUST 仅接受实际字节与媒体类型均为 PNG 或 JPEG 的资产，且每个引用该处理
的映射 MUST 以正面或背面丝印层为目标。只有当前制造配置显式支持彩色丝印时系统才可保存
或执行该模式；否则 MUST 返回包含如何启用合法彩色丝印配置或改回标准丝印的可操作错误。

#### Scenario: 彩色原图映射到铜层
- **WHEN** 用户把 `colorOriginal` 处理映射到铜层或阻焊开窗
- **THEN** 系统必须拒绝该修改并说明彩色原图只能用于丝印层

#### Scenario: 彩色原图使用不支持的素材
- **WHEN** 用户把 SVG、WebP 或伪装为 PNG/JPEG 的其他字节设置为 `colorOriginal`
- **THEN** 系统必须拒绝该模式并明确要求真实 PNG 或 JPEG 素材

#### Scenario: 当前制造配置不支持彩色丝印
- **WHEN** 用户在标准字符工艺或不满足彩色丝印组合约束的制造配置中启用 `colorOriginal`
- **THEN** 系统必须拒绝该修改，并提示启用合法彩色丝印配置或改用 `monochromeMask`
