## Requirements
### Requirement: 显式生产层栈
系统 MUST 编译并显示顶铜、顶阻焊开窗、顶丝印、底铜、底阻焊开窗、底丝印、板框和钻孔。
系统必须将基材、阻焊颜色与表面处理作为基础叠层信息，而不是内容图层。

#### Scenario: 查看正面生产层栈
- **WHEN** 用户在编辑模式选择正面生产层工作节点
- **THEN** 系统必须显示基材上的顶面生产层，并允许独立显示或隐藏每个生产层

### Requirement: 生产层映射与调整
系统 MUST 允许用户通过生产层对象树添加、移除和检查目标生产层关联，并允许在编辑模式左侧树中进行
显隐、隔离和基础叠层选择；生产层调整不得隐式改变其他层的极性。编译后的生产层 MUST
作为可追溯的派生结果呈现，不得作为普通内容对象直接编辑。

#### Scenario: 将文字关联为顶丝印
- **WHEN** 用户将铜层文字高级关联到顶丝印
- **THEN** 两个生产层下必须显示同一源对象的关联项，2D 预览按各自生产层显示结果

#### Scenario: 隔离生产层不改变导出
- **WHEN** 用户临时隔离顶丝印以检查细节
- **THEN** 系统只能改变当前生产预览的显隐，任何内容层的导出参与状态和映射均不得改变

#### Scenario: 从生产图形追溯内容
- **WHEN** 用户检查生产层中的一个已编译图形
- **THEN** 系统必须允许定位其来源内容层和映射，不得要求用户编辑派生纹理

### Requirement: 生产层是预览真相
2D 生产预览 MUST 消费已编译生产层，而不是直接渲染内容画布；预览与导出必须共享物理
尺寸、原点、固定生产网格、板框裁切、层极性和正反面语义。图片、文字和内容变换
MUST 在统一编译阶段解析为最终生产 mask；预览和导出器不得各自重新栅格化内容。

#### Scenario: 检查阻焊开窗极性
- **WHEN** 用户预览一个映射到顶阻焊开窗的非对称图案
- **THEN** 预览必须将图案表示为不盖阻焊的开窗，并与编译生产层的几何完全一致

#### Scenario: 预览与导出消费相同生产 mask
- **WHEN** 用户编译包含图片和文字的卡片并随后预览和导出
- **THEN** 两条路径必须消费同一个带输入哈希与栅格器版本的最终生产 mask，且不得再次读取源图片或系统字体

### Requirement: 背面生产预览
系统 MUST 让编辑态背面生产层纹理与正向设计画板对齐，不得镜像可编辑对象。物理翻面
观看方向 MUST 仅用于 3D 成板预览或用户显式进入的生产检查，同时保持底层生产几何处于
板坐标中。

#### Scenario: 检查非对称背面标记
- **WHEN** 用户在背面编辑态查看包含非对称 `B` 标记的生产层
- **THEN** 标记必须与正向背面内容对齐且保持正立，领域坐标和导出坐标不得因此被修改

### Requirement: 整体 3D 成板预览
系统 MUST 在顶层预览模式中提供只读的整体 3D 成板视图。板体比例、板框、孔、正背面
生产图形与叠层颜色 MUST 消费 `ResolvedFabricationBoard` 和 `StackupPreset`，不得
从内容画布另行近似生产几何。用户 MUST 能拖动旋转、缩放和平移相机。

#### Scenario: 旋转查看正反面
- **WHEN** 用户拖动 3D 板体从正面旋转到背面
- **THEN** 系统必须连续显示符合物理观看方向的正背面材质，且不得修改领域坐标或导出方向

#### Scenario: 预览中尝试编辑
- **WHEN** 用户在 3D 预览中点击或拖动板上图形
- **THEN** 系统只能改变相机或查看状态，不得修改内容层、生产映射或命令历史

### Requirement: 预览响应与版本一致性
系统 MUST 按资产哈希、处理配方指纹、物理尺寸、裁切、代理精度和算法版本缓存并复用交互结果，
使图片处理器、对象级编辑代理、显式 2D 生产检查与 3D 成板预览来自同一版本化处理语义。
Tauri MUST 在后台执行图片处理、首次生产板编译和纹理编码，不得同步阻塞桌面 UI。注册源图片
后的请求不得以 JSON 数字数组重复传输源图或完整 RGBA 缓冲区；跨运行时的代理结果 MUST 使用
紧凑图片编码或受控资源引用。

每个由 `(workspaceId, previewStreamId)` 唯一标识的图片交互流至多 MUST 有一个正在运行的
处理任务和一个代表最新 generation 的待处理请求。同一源资产的不同实例或独立编辑手势 MUST
使用不同 preview stream；相同稳定代理键仍可由共享 broker 跨流合并。
新的请求 MUST 覆盖尚未开始的旧请求，并使运行中的旧任务在阶段边界或分块检查点协作取消。
检查器和画布 MUST 通过共享代理 broker 订阅结果；较高精度代理只能在输入空闲后按离散档位
生成，不得由每个滑块或滚轮事件分别触发。

#### Scenario: 编辑后切换 3D 预览
- **WHEN** 用户确认图片配方后切换到预览
- **THEN** 3D 必须使用已提交 revision 和配方指纹编译出的对象，交互 draft 或较旧结果不得进入正式成板纹理

#### Scenario: 普通编辑不重复叠加生产纹理
- **WHEN** 用户在编辑模式插入或查看已映射的图片和文字，且尚未显式开启生产检查
- **THEN** 画布必须只显示一个可编辑生产近似对象，编译后的完整生产纹理不得默认叠加造成重影

#### Scenario: 移动对象不重建图片处理结果
- **WHEN** 用户连续拖动、缩放或旋转处理后的图片
- **THEN** 编辑器必须仅变换已有客户端代理纹理，图片解码、配方处理、代理请求和正式生产板编译计数在手势期间均保持不变

#### Scenario: 缩放提交后等待新尺寸代理
- **WHEN** 用户结束图片缩放手势，新的物理尺寸触发含重平滑处理的代理请求
- **THEN** 编辑器必须继续按新几何缩放显示上一张可用纹理而不得显示空白或占位矩形，过时处理必须在形态学行块内协作取消，且 `interactive-image-v1` 的 20 次尺寸 burst 最终代理必须在当前 macOS 基准机上于 250 ms 内可用

#### Scenario: 修改图片处理配方
- **WHEN** 用户连续调整阈值、平滑或去斑参数
- **THEN** 系统必须保留上一份可用代理并只接受最新 generation，在用户停止输入后再按需提升代理精度，且不得被陈旧结果覆盖

#### Scenario: 检查器与画布共享代理
- **WHEN** 检查器和当前画布需要同一图片配方与精度档位
- **THEN** 共享代理 broker 必须只启动一次处理并让两个消费者复用结果，任一消费者卸载不得提前释放仍被另一消费者使用的纹理

#### Scenario: 复用同一 revision 的生产板
- **WHEN** 显式 2D 检查与 3D 成板预览连续请求同一工程 revision 和处理配方
- **THEN** WorkspaceService 必须只解析一次生产板，并让两个响应携带相同的生产输入与输出哈希

#### Scenario: 修改阻焊颜色
- **WHEN** 用户将板体阻焊颜色从哑黑改为白色
- **THEN** 编辑工艺近似必须立即更新，正反面最终成板纹理也必须使用白色阻焊效果，即使六层生产 mask 的几何哈希未变化

### Requirement: 编辑近似与正式生产几何一致
系统 MUST 使用非对称图片、文字、孤岛、细线、孔洞和开窗黄金样例比较对象级编辑代理、3D 成板
和正式生产 mask。显示色彩和采样精度 MAY 不同；对于宽度、直径和间隙不小于两个当前代理像素
的结构，其边界、连通关系、孔洞拓扑、组合极性、生产层归属、裁切和正背方向不得不同。低于该
档位可表达范围的细节 MAY 等待更高精度代理，但不得改变正式输出或被误报为已通过制造检查。
交互代理不得通过改变算法语义换取速度；只允许复用预处理数据、降低采样密度或延迟非当前观察窗
所需的精度提升。

#### Scenario: 黄金图片跨精度验证
- **WHEN** 自动化以交互、3D 和正式导出三种精度处理同一图片配方
- **THEN** 测试必须验证配方指纹一致、可表达结构的轮廓误差不超过一个对应精度像素且拓扑相同，并验证低于代理表达范围的细节只影响代理显示、不改变正式结果、极性、裁切或方向

#### Scenario: 放大编辑图片生产代理
- **WHEN** 用户在编辑画布将处理后图片从适配视图连续放大到 400%
- **THEN** 编辑器必须在滚轮输入停止后按离散精度档位提高对象代理密度，使最高缩放下一个代理像素不超过一个 CSS 像素，同时复用同档缓存且不得在每个滚轮事件重新编译

### Requirement: 真实图片负载的交互性能契约
系统 MUST 按版本化 `interactive-image-v1` benchmark profile 在 Tauri 发布构建中，以固定
SHA-256 的约 1000×1500 像素真实 PNG/JPEG、固定 51.17×80 mm 物理尺寸和 250 µm warm
prepared-source 代理测量图片交互性能，并记录源字节传输量、解码次数、代理编译次数、活动任务数、
陈旧任务取消数、预览延迟和画布帧时间。profile MUST 记录应用 commit、硬件、系统、供电模式、
fixture 哈希、代理输出尺寸、采样数和计时边界。预览延迟从输入事件派发计至对应 generation 的
纹理解码完成并可绘制，至少采集 30 个非缓存阈值/反相结果；拖动至少采集 300 帧。基准 MUST
证明注册完成后的参数请求不再携带源图、同对象并发受限、拖动零编译，并在 profile 指定的当前
macOS 基准机上将阈值或反相变化后的首个新代理反馈控制在 120 ms p95、画布拖动帧更新控制在
16.7 ms p95；较重的形态学处理 MAY 延后完成，但不得阻塞输入或显示陈旧结果。

#### Scenario: 连续拖动阈值滑块
- **WHEN** 自动化以高于处理吞吐的频率连续发送 60 个阈值输入并等待最后结果
- **THEN** 前端输入事件处理 p95 必须低于 16.7 ms，后端不得为 60 个中间值逐个完成正式处理，最终显示必须对应第 60 个 generation

#### Scenario: 处理任务运行时拖动画布对象
- **WHEN** 一个较重的去斑或最小特征代理仍在后台运行且用户拖动该图片
- **THEN** 拖动必须继续使用已有纹理并满足帧时间目标，后台任务不得同步占用前端事件路径或触发几何提交前的 document 写入

#### Scenario: 连续提交图片物理尺寸
- **WHEN** 自动化对同一真实图片以 25 µm 高倍率代理精度连续发送 20 个不同物理尺寸和 UI 可达上限 1 mm 平滑半径的 generation
- **THEN** 至少 18 个过时请求必须取消，最终 generation 必须正确且在当前 macOS 基准机上于 250 ms 内完成，不得等待旧的平方复杂度平滑任务跑完

#### Scenario: 真实画布缩放等待代理刷新
- **WHEN** 用户拖动真实 Konva Transformer 缩放已处理图片，提交后新的画布代理响应被延迟或失败
- **THEN** pointerup 前不得发起画布代理编译，等待期间连续 30 个采样帧必须按新几何显示上一张纹理且有效像素不得下降超过首帧的 20%，代理失败后也不得退化为空白或占位矩形
