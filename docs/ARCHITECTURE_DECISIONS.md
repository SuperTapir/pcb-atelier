# 架构决策记录

本文档记录 PCB Atelier 当前已经落地的架构约束，以及仍待集成或验收的选择。

## 已确定

### 产品是 PCB 艺术创作工作台

产品面向艺术板，不以替代完整电子 EDA 为目标。复杂电路设计继续交给专业 EDA。

### 生产层是真相来源，预览是制造前的决策工具

2D 生产预览、3D 实体材料预览、生产层导出、EasyEDA 和 Gerber 必须来自同一份
生产几何，不能分别实现近似效果。位置、物理尺寸、旋转、镜像、板框裁切、孔位和
层极性必须一致；3D 中的沉金色泽、铜反光和阻焊质感可以是可信近似，但不能掩盖
制造几何。

EDA 是最终制造复核和复杂电路设计的出口。对于简单艺术板，用户应能在产品中完成
主要制作并直接生成制造文件；对于复杂任务，产品应提供可继续编辑的高质量初稿，
而不是要求用户从 EDA 重新开始图片处理和版面调整。

### 源对象与生产层分离，但不暴露独立“内容模式”

内部内容层表达图片、文字、组和基础铺铜等稳定源对象；生产层表达顶铜、顶阻焊
开窗、顶丝印、底铜、底阻焊开窗、底丝印、板框和钻孔。一个源对象可以写入多个
同面生产层，一个生产层也可以组合多个源对象。

用户界面不再提供独立“内容”入口或“内容 / 生产 / 材质”顶层模式。左树直接采用
“板体 → 正面/背面 → 铜/阻焊开窗/丝印”的生产语言；树下条目和多层“关联”仍回指
内部同一个源对象及显式映射。这避免复制对象和坐标，同时不要求普通用户理解两套树。

### 项目绑定资产及其派生关系

当前 `.pcba` 将位图资产嵌入项目并校验路径和 SHA-256，保存源对象、整数微米变换
和生产层映射。外链资产、非破坏图像处理链、人工修正来源和导出快照尚未实现，不能
作为当前 schema 契约。

### GUI、CLI 和 Agent 共用核心

界面操作必须能够表达为统一工程命令。CLI 不是后期包装，未来 Agent 也不通过
模拟点击修改工程。

### 不兼容旧工程 schema

新项目不承担 PCB_lightgraph Neo 旧工程的运行时兼容成本。若未来需要迁移，
使用独立一次性转换工具。

### 项目容器格式

首版使用扩展名为 `.pcba` 的可解压项目包，包含带版本的 JSON 清单和嵌入资产。
保存时先写入同目录临时文件，完成结构与内容校验后再原子替换目标。外链资产与导出
快照在后续变更中扩展，但不得破坏现有 schema 的版本边界。

### 核心数据表示

`AtelierDocument` 使用整数微米保存板框、正反面内容树与变换；`ProductionMapping`
显式描述内容到顶/底铜、阻焊开窗和丝印的添加/挖空关系。画布节点不是工程真相。
统一编译器先生成可追溯的 `FabricationPlan`，再以固定生产网格解析为
`ResolvedFabricationBoard`；2D 生产预览和 EDA 导出只能消费后者。
GUI、CLI 和未来 Agent 调用同一组可序列化领域命令与撤销/重做历史。

板体改变是领域命令，不是画布缩放：`SetBoardOutline` 保持所有对象的物理变换，
以诊断返回旋转后包围框越界；`SetStackup` 修改板厚、阻焊颜色和表面处理。基材当前
固定为 FR-4。基础铺铜每面最多一个，重复创建返回已有稳定 ID；映射命令在 Core
边界拒绝跨面和铺铜到非铜层。

### GUI 技术栈

直接继承 PCB_lightgraph Neo 已验证的技术底座：

- Tauri 2 桌面外壳；
- React + TypeScript + Konva 对象画布；
- Tailwind CSS v4；
- shadcn/ui；
- 独立 Rust Core；
- Vitest、Playwright 与 Rust 测试。

Konva 只负责图片、文字、选择框、控制点和吸附线。生产层由 Rust Core 编译为少量
纹理，通过可替换的 `ProductionRenderer` 接口显示；若真实性能基准不合格，可以将
生产渲染替换为 PixiJS/WebGL/WebGPU，而不改变领域模型。

工作区顶层只保留“编辑 / 预览”。编辑采用左侧生产语言图层树、中间正背双画板、右侧
上下文检查器；预览采用只读 Three.js 整体成板视图。工具、活动卡面、同时查看/聚焦
布局与顶层模式互相正交，两面分别保存选择和视口。

铜、阻焊开窗和丝印以特殊工作节点出现在左侧，但它们只创建或定位源内容与生产映射，
不会把已编译纹理变成普通对象。内容显隐、锁定、选择和是否参与导出是四个独立语义。

图片和文字插入遵循当前活动卡面与工作层，创建源对象后自动增加当前生产层的 `add`
映射；检查器允许同一对象关联其他同面生产层。阻焊明确使用“添加开窗 / 减少开窗”
措辞，基础铺铜只能位于所在面的铜层。

### Web 与 Tauri 共享 WorkspaceService

Tauri `workspace_invoke` 和本地 Web `workspace-bridge` 都是薄传输 adapter，共同调用
Rust `WorkspaceService`。请求/响应使用 `pcb-atelier-workspace-v1`、revision、
payload/error 契约；读操作不增加 revision。Web bridge 只监听 localhost，并只在
Vite 开发模式通过代理使用；production Web 后端和 Web 目录选择尚未实现。

Rust 契约测试已验证当前文档预览、版本字段与 Tauri adapter 等价。浏览器 E2E 和
Tauri 实际交互是不同验证层，尚不能因为 adapter 单测通过就宣称完整桌面流程通过。

### EasyEDA 交接等级

本轮目标是生成嘉立创 EDA 可打开并继续检查的 `.eprj2` 工程。转换采用公开
`.epro2` 归档作为中间表示，并对最终工程做结构验证。该出口保持单向；用户在 EDA
中的后续编辑不回写 Atelier 工程。

## 待验收

- 双 Konva Stage、合计两百对象的独立性能基准已在 Chrome 和 Tauri release
  WKWebView 达到 45 FPS 与内存门槛；仍需在完整工作区长期操作中继续观察；
- Web、Tauri、3D 预览和“导出 EDA”按钮的最终真实交互验收；
- 首版基础图像处理的确切集合，仍需由真实艺术卡样本确定，不在编辑器基础切片中扩张。


## 决策方法

每项重大能力进入实现前必须回答：

1. 它解决哪个真实、重复发生的制作问题？
2. 对应的黄金样本和失败案例是什么？
3. GUI、CLI 和导出怎样共享同一语义？
4. 如何验证进入 EDA 或 Gerber 后没有变样？
5. 如果暂时不做，用户能否通过 PS 或 EDA 完成？

不能回答这些问题的能力，不进入首版。
