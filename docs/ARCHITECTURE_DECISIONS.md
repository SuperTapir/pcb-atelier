# 架构决策记录

本文档记录 PCB Atelier 在正式实现前已经明确的约束，以及仍需讨论的选择。

## 已确定

### 产品是 PCB 艺术创作工作台

产品面向艺术板，不以替代完整电子 EDA 为目标。复杂电路设计继续交给专业 EDA。

### 生产层是真相来源

实体预览、生产层导出、EasyEDA 和 Gerber 必须来自同一份生产几何，不能分别
实现近似效果。

### 内容图层与生产层分离

内容图层表达人物、Logo、文字、线稿、蒙版等创作对象；生产层表达顶铜、顶阻焊
开窗、顶丝印、底铜、底阻焊开窗、底丝印、板框和钻孔。

一个内容图层可以写入多个生产层，一个生产层也可以组合多个内容图层。

### 项目绑定资产及其派生关系

项目同时支持嵌入资产和链接外部资产，并保存内容处理、物理变换、生产层映射、
人工修正、来源与导出快照。

### GUI、CLI 和 Agent 共用核心

界面操作必须能够表达为统一工程命令。CLI 不是后期包装，未来 Agent 也不通过
模拟点击修改工程。

### 不兼容旧工程 schema

新项目不承担 PCB_lightgraph Neo 旧工程的运行时兼容成本。若未来需要迁移，
使用独立一次性转换工具。

## 待决定

### 项目容器格式

候选方向：

- 一个可解压的项目包，内部包含清单、嵌入资产、蒙版和导出快照；
- 普通目录工程，使用相对路径管理资产；
- 开发期使用目录，发布期提供可打包容器。

选择标准：可读、可 diff、可迁移、可部分恢复，并能容纳大型图片资产。

### 核心数据表示

需要决定：

- 内容层和处理栈的 schema；
- 栅格与矢量内容的统一边界；
- 蒙版、增加和挖空的表示；
- 生产层编译后的中间几何格式；
- 命令、撤销和差异记录格式。

### GUI 技术栈

直接继承 PCB_lightgraph Neo 已验证的技术底座：

- Tauri 2 桌面外壳；
- React + TypeScript；
- Tailwind CSS v4；
- shadcn/ui；
- 独立 Rust Core；
- Vitest、Playwright 与 Rust 测试。

继承的是技术架构和应用图标，不是旧 UI、旧业务状态或旧工程 schema。任何 UI
框架都不能反向定义核心工程模型。

### EasyEDA 交接等级

需要通过黄金样本决定首版承诺：

- 生成可继续编辑的 EasyEDA 工程；
- 生成 EasyEDA 可直接导入的生产资产；
- 或以 Gerber 为主要下单出口，EasyEDA 仅用于复核。

### 图像处理的首版边界

规划已经限定为基础非破坏处理，但仍需用两个黄金样本确定最小集合，避免再次
实现一批没有真实用途的算法选项。

## 决策方法

每项重大能力进入实现前必须回答：

1. 它解决哪个真实、重复发生的制作问题？
2. 对应的黄金样本和失败案例是什么？
3. GUI、CLI 和导出怎样共享同一语义？
4. 如何验证进入 EDA 或 Gerber 后没有变样？
5. 如果暂时不做，用户能否通过 PS 或 EDA 完成？

不能回答这些问题的能力，不进入首版。
